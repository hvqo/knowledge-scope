# 对话工作区

`/chat` 是一个持久化的知识库问答工作区：对话与消息保存在 PostgreSQL，界面按主流对话产品的习惯组织成「左侧历史列表 + 中间消息流 + 右侧来源面板」。它复用现有的 RAG 流式接口生成回答，不新增检索或生成路径。

## 数据边界

对话由 `ChatConversation` 和 `ChatMessage` 两张表组成，迁移为 Alembic `0008_create_chat_conversations`。

- 对话保存标题、可选的知识库以及创建/更新时间；标题在第一次提问时自动取问题前 30 个字符。
- 消息保存角色（`user` / `assistant`）、状态（`complete` / `error`）、正文、位置序号和引用元数据；位置序号保证消息按阅读顺序稳定返回，不依赖时间戳。
- 引用只保存 RAG 已经生成并经过校验的 `RAGCitation`（文档、页码、块标识、证据标识、片段与检索分支）。prompt、token、provider 明细和模型原始输出都不会写入对话。
- 对话绑定知识库使用 `ON DELETE CASCADE`：知识库被删除时，依赖它的对话与消息一并删除；消息随对话级联删除。
- 空对话不会落库。「新对话」只是清空当前选择，第一次提问时才创建记录，避免历史列表堆满空行。

## API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/chat/conversations` | 按最近活跃排序的对话列表（含消息条数） |
| POST | `/api/v1/chat/conversations` | 创建对话，可绑定知识库 |
| GET | `/api/v1/chat/conversations/{id}` | 对话详情与全部消息 |
| PATCH | `/api/v1/chat/conversations/{id}` | 重命名或改绑知识库 |
| DELETE | `/api/v1/chat/conversations/{id}` | 删除对话及其消息 |
| POST | `/api/v1/chat/conversations/{id}/messages` | 追加一条问题或回答 |

校验规则：标题折叠空白且不可为空；正文不可全为空白；`user` 消息不允许携带引用且状态固定为 `complete`；同一回答的引用标记必须唯一；引用数量上限 100。知识库或对话不存在返回 404，请求体不合法返回 422。写入消息会同时刷新对话的 `updated_at`，因此列表顺序始终跟随最新活动。

回答仍然通过 `POST /api/v1/rag/query`（SSE）生成，服务端不保存流式中间态：客户端先保存问题，把流式结果渲染在内存中，完成（或失败、或用户停止）后再保存回答。这样跨 PostgreSQL、Qdrant、Neo4j 和 LLM 的调用之间不构成分布式事务；保存失败时回答仍留在界面上，只是提示未能写入历史。

追问会把最近几轮问答（最多 8 条、每条截断到 2,000 字符）作为 `history` 一起发送，让「再展开讲讲」这类问题能接上上下文；服务端只把它用于生成，不会绕过检索，历史中的引用标记也会被剥离。

输入区下方可以切换检索范围：「智能」（默认，元问题直接回答、简单问题走向量检索、复杂问题自动多路检索）、「深度」（向量 + 关键词 + 图谱 + 多模态，覆盖更全）与「快速」（仅向量检索，明显更快）。追问会被改写成可独立检索的问题，改写结果会显示在来源面板里；智能档下一旦发现快速检索证据不足会自动扩展为多路检索并在来源面板提示，重复问题命中检索缓存时秒级返回。回答（尤其是缓存命中的整段返回）按打字机节奏逐段显示，不会一次性糊一屏；系统开启「减少动态效果」时改为立即显示全文。回答中的 `[Cn]` 会渲染成可点击的引用胶囊，模型偶尔把标记单独成行时前端会把它贴回所属句子，其余排版与标点不做改动。
## 项目、长期记忆与上下文管理

- **项目**：对话可以归入项目（类似 ChatGPT 的 Projects）。`POST /chat/projects` 建项目、
  `PATCH /chat/conversations/{id}` 的 `project_id` 移动对话、`DELETE /chat/projects/{id}` 删除项目
  （对话保留，回到未分组）。侧边栏采用「项目 / 最近」两段结构：「项目」区头部有 ＋（新建）、···（收起全部）、↻（展开全部）三个操作，每个项目行可展开查看其中的对话，并支持重命名与删除；「最近」区列出未归入项目的对话，每个对话都能通过 ⇢ 移入项目或移出。
- **长期记忆**：按知识库隔离的跨对话记忆（`chat_memories` 表）。每轮回答完成后前端会静默调用
  `POST /chat/memories/extract`，由一次小模型调用从对话中提炼值得长期记住的信息（去重、过滤已有表述、
  上限 50 条），失败一律静默跳过。后续提问时，最近的记忆作为「背景信息」注入提示词
  （明确不是资料、不得引用、与问题无关时不使用），`complete.memories_used` 回填条数；
  记忆可在侧边栏「长期记忆」面板查看、手动添加与删除。`KNOWLEDGE_SCOPE_CHAT_MEMORY_ENABLED=false` 可整体关闭。
- **上下文压缩**：历史不再超过 12 轮就报错——最近 8 轮（`rag_history_recent_turns`）保留原文，
  更早的轮次由一次 LLM 调用压成滚动摘要作为背景注入；压缩失败时降级为丢弃旧轮次，不影响提问。
- **上下文缓存命中**：压缩摘要按「被压缩轮次的内容」缓存（`chat:summary:` 前缀，TTL 24h），
  旧轮次不变时追问直接命中，不再重复调用压缩模型；`complete.history_cache_hit` 回填命中情况，
  `history_compressed_turns`/`history_summary_used` 回填压缩规模。配合检索缓存与追问改写缓存，
  重复问题的检索与压缩开销都趋近于零。

回答正文按 Markdown 子集渲染（`##` 小标题、无序/有序列表、`**加粗**`、行内 `code`），段落之间留白，列表项独立成行，不再是一整块文字；解析器只识别这几种语法，其余内容原样显示。数学公式用 KaTeX 渲染（行内 `$…$`、独立成行 `$$…$$`）：公式包按需加载，只有回答里真的出现公式时才拉取（对话页自身约 29 KB，公式块约 262 KB / 78 KB gzip）；KaTeX 解析失败时显示公式源码而不丢内容，金额/编号这类普通 `$` 不会被当成公式。对话页只保留必要信息：标题栏不再重复「正在使用某个知识库」，知识库选择器下方与输入框下方也去掉了说明性文案，侧边栏品牌位与助手头像使用 `frontend/imgs/icon.jpg`。问候、致谢和「你能做什么」这类元问题由服务端路由直接回答，不检索资料也不调用模型，因此是即时返回；这类回答没有引用标记，也不会显示来源按钮。详见 [RAG QA](rag-qa.md)。

## 前端工作区

`/chat` 使用整块工作区：左侧栏提供「新对话」、提问依据的知识库选择与历史对话列表；中间是居中的消息列；右侧来源面板默认收起，点击回答里的引用标记或「来源」按钮后展开。

- 历史对话支持重命名（就地编辑，回车保存）、删除（二次确认）与切换；正在进行回答时这些操作会被禁用。
- 切换提问依据会写回当前对话；对已有回答的对话改绑只影响之后的问题，界面会明确提示。
- 消息列区分用户气泡与助手正文，助手消息带引用标记、复制与「来源」操作；流式过程中显示生成光标与「正在阅读资料…」。
- 「来源 N」只统计回答正文中真正引用到的标记（服务端会返回本次检索到的全部候选）。像「你能做什么」这类元问题的回答不含引用标记，因此不会显示来源按钮。
- 回答失败会写入 `error` 状态并在界面保留提示，用户停止生成时保留已有内容；两者都能在历史里回看。
- 窄屏下左侧栏与来源面板都改为覆盖式抽屉，避免压缩消息列。

服务端状态（对话、消息、知识库、文档标题）全部通过 Vue Query 读取，Pinia 只保存当前选中的知识库、当前对话和抽屉开关这类界面状态。
