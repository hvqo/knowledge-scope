# 报告创作工作区

报告创作工作区用于把知识库证据和业务数据分析结果整理成一份可继续编辑的报告。当前支持持久化编辑、来源引用、AI 预览和服务端 DOCX/PDF 导出；不负责协同编辑或版本历史。

## 数据边界

报告由 `Report`、`ReportSection` 和 `ReportSourceReference` 组成。报告可以关联一个知识库和一个已注册数据源；章节保存标题、纯文本正文和稳定顺序；来源引用只允许两种类型：`rag_evidence` 与 `chatbi_result`。来源列表按 `created_at`、`id` 的显式顺序返回，顺序稳定但不把数据库隐式顺序作为契约。

来源引用使用有界的结构化字段保存渲染和后续引用所需的信息：文档、页码、证据类型、证据/块标识、章节路径、问题、答案、列、行、截断状态、脱敏 SQL 和有限图表规格。不会保存 provider trace、prompt、token、凭据或评测状态。ChatBI 来源只接受现有 `/chatbi/data-sources/{id}/ask` 返回的安全结果，执行仍经过现有资格判断、SQL 校验和只读执行路径。

## API 与生命周期

REST API 位于 `/api/v1/reports`：报告和章节支持列表、创建、更新、删除；章节来源支持有界创建和删除。创建来源时，服务端会重新校验报告与知识库/数据源的关联，并确认 RAG 文档属于当前知识库。删除报告或章节会级联删除其来源引用；报告本身对关联知识库和数据源使用 `RESTRICT`，避免静默改变报告上下文。

章节正文和来源引用的写入由前端的显式操作触发。跨请求的“插入来源 + 更新正文”不是分布式事务；若第二个请求失败，界面会保留安全错误并允许用户重试或删除已保存来源。数据库迁移由 Alembic `0007_create_reports` 管理。

## 前端工作区

`/reports` 展示报告列表并复用知识库、数据源列表 API；`/reports/:id` 使用三列布局：左侧大纲，中间章节编辑/预览，右侧来源面板。RAG 查询复用现有 SSE 查询接口和 Evidence 语义，ChatBI 查询复用现有结果表格和确定性图表组件。切换或离开报告时，脏草稿会先保存；保存失败会阻止导航，浏览器刷新或关闭时只显示标准离开提示，不尝试异步保存。请求在离开工作区时取消，来源和草稿更新使用当前报告/章节 ID，避免把旧请求写入新章节。

工作区提供“生成大纲”“生成本章节”“改写”“扩写”“精简”操作。AI 结果先进入可编辑预览，用户接受后才追加章节或放入当前草稿；正文仍需显式保存。生成请求只读取当前报告、章节和有界的已持久化来源，不会修改报告数据库，也不会把 provider trace、prompt、token 或原始响应保存到报告中。

生成使用现有 `LLMGateway`，任务类型为 `report_generation`，提示版本为 `report-generation-v1`，默认关闭 reasoning、单次输出上限为 2,048 tokens。该配置只服务于报告预览，不改变 ChatBI 的 NL2SQL 或分析配置。前端为每个 AI 请求保存报告 ID、请求序号和可取消信号；切换/离开报告或发起更新请求时，旧请求会被取消，迟到结果会被丢弃。

引用标记由模型使用 `R1` 等临时 key 表示，服务端会先解析正文中的全部 `[R<number>]` 标记，再逐一映射到本报告已有的 `ReportSourceReference`；未知、越界或格式不完整的标记，重复 JSON 字段、额外字段和非 JSON 响应都会被拒绝。模型不能提供内部来源 ID，也不能凭空创建引用。导出只读取已持久化报告状态，正文、章节、表格快照和来源清单会写入 DOCX/PDF；当前没有可安全解析的图片资产引用时不会生成占位图片或虚假链接。

DOCX 使用无临时文件的 OOXML 生成，PDF 使用服务端 CJK CID 字体生成；PDF 的 ChatBI 表格先输出持久化列名，再输出有界数据行。文件名经过长度和路径字符限制，响应不暴露服务器路径。单次导出最多包含 100 个章节、256 条来源引用、1,000,000 个正文/来源字符和 50,000 个 ChatBI 单元格；超过任一上限会在渲染前返回受控的 422，不会静默截断或生成部分文件。导出和 AI 预览均属于跨服务操作：LLM 调用、数据库写入和文件响应不构成全局事务；生成失败不会改变报告，导出失败也不会改变报告。
